# The opcode handlers (`session/handlers/`)

One directory per domain, and `connection/` for the requests of the client's connection itself, which belong to no domain; one class per origin file in its directory; combat's class, made from two files, and pvp's, the class of both the arena team and the battleground files, are the two exceptions. A handler class is stateless: static entry points only, each `static void HandleX(WorldSession& session, WorldPacket& packet)`, bound by the rows of `Server/OpcodeTable.cpp` through `OpcodeThunk`; status and processing stay table metadata. A handler reaches the session through its public members and borrows it by reference for one call, on the world thread or on the map worker that owns the player's map; `World` owns the sessions and deletes them only between calls. A handler keeps nothing: no data member, no static variable but a prepared statement's cached id (`static SqlStatementID`), no session or player pointer in anything that outlives the call. It reads the player through `session.GetPlayer()`, and takes the pointer fresh after any call that can log the player out. Work that finishes later captures ids and values only, never a session or player pointer, and finds what it needs again when it runs by those ids, or by ids a query keyed on them returns: the requester through `WorldSession::FindRequesterSession` or, with the guid checked too, `WorldSession::FindRequesterPlayer`, which drop the answer when a reconnect has replaced the session, and any other player by guid through the player registry.

|---|---|---|
| `combat/` | `CombatHandlers` | the client's melee swing, attack stop and sheath (`CMSG_ATTACKSWING`, `CMSG_ATTACKSTOP`, `CMSG_SETSHEATHED`) and duel accept and cancel (`CMSG_DUEL_ACCEPTED`, `CMSG_DUEL_CANCELLED`); `SendAttackStop`, the `SMSG_ATTACKSTOP` the swing sends when it refuses a target, is its private static |
| `connection/` | `WardenHandlers` | the client's Warden data (`CMSG_WARDEN_DATA`) on an authenticated session, drained and ignored: the server runs no Warden, and `CheckDormantWardenBoundary` keeps the row and the body that way |

| `economy/` | `LootHandlers` | the client's loot window open and close (`CMSG_LOOT`, `CMSG_LOOT_RELEASE`), item and currency taking (`CMSG_AUTOSTORE_LOOT_ITEM`, `CMSG_LOOT_CURRENCY`, both bound to one static), money taking (`CMSG_LOOT_MONEY`) and the master looter's give (`CMSG_LOOT_MASTER_GIVE`); `DoLootRelease`, which the logout, the logout request and the player's own loot opening (`Player::SendLoot`) also call, stays on `WorldSession` in `WorldHandlers/LootHandler.cpp` |
| `economy/` | `TradeHandlers` | the client's trade request and window open (`CMSG_INITIATE_TRADE`, `CMSG_BEGIN_TRADE`), the notices of a request ignored or met busy (`CMSG_IGNORE_TRADE`, `CMSG_BUSY_TRADE`), the offer's gold, item and item clearing (`CMSG_SET_TRADE_GOLD`, `CMSG_SET_TRADE_ITEM`, `CMSG_CLEAR_TRADE_ITEM`), accept and unaccept (`CMSG_ACCEPT_TRADE`, `CMSG_UNACCEPT_TRADE`) and cancel (`CMSG_CANCEL_TRADE`); `moveItems`, which stores each side's traded items in the other's bags, is its private static; the class is `Player`'s friend for the player's trade data, which the request creates and the completed trade deletes; the trade senders stay on `WorldSession` in `WorldHandlers/TradeHandler.cpp`: `SendTradeStatus` and `SendUpdateTrade`, which the trade data's own members (`TradeData` in `entities/player/Player.cpp`) also call, and `SendCancelTrade`, which `Player::TradeCancel` calls |
| `economy/` | `VendorHandlers` | the client's vendor sell, buyback, buy and inventory list (`CMSG_SELL_ITEM`, `CMSG_BUYBACK_ITEM`, `CMSG_BUY_ITEM`, `CMSG_LIST_INVENTORY`), bag auto-store (`CMSG_AUTOSTORE_BAG_ITEM`) and bank slot purchase and bank auto-store (`CMSG_BUY_BANK_SLOT`, `CMSG_AUTOBANK_ITEM`, `CMSG_AUTOSTORE_BANK_ITEM`); `SendListInventory` and `CheckBanker`, which callers outside the class use, stay on `WorldSession` in `WorldHandlers/ItemHandlerVendor.cpp` |
| `entities/` | `EnchantHandlers` | the client's gift wrapping of an item (`CMSG_WRAP_ITEM`), gem socketing (`CMSG_SOCKET_GEMS`) and the cancelling of a temporary enchantment on an equipped item (`CMSG_CANCEL_TEMP_ENCHANTMENT`); the enchantment senders stay on `WorldSession` in `WorldHandlers/ItemHandlerEnchant.cpp`: `SendEnchantmentLog`, which the item's enchantment change (`Item::SetEnchantment`) calls, and `SendItemEnchantTimeUpdate`, which the player's enchantment durations (`Player::AddEnchantmentDuration`, `Player::SendEnchantmentDurations`) call |

| `entities/` | `TaxiHandlers` | the client's flight master opcodes: a taxi node's status (`CMSG_TAXINODE_STATUS_QUERY`), the flight map opened at a flight master (`CMSG_TAXIQUERYAVAILABLENODES`, `CMSG_ENABLETAXI`, both bound to one static), a flight over two nodes (`CMSG_ACTIVATETAXI`) or over a route (`CMSG_ACTIVATETAXIEXPRESS`), and the spline-done ack (`CMSG_MOVE_SPLINE_DONE`), read and ignored; the taxi senders stay on `WorldSession` in `WorldHandlers/TaxiHandler.cpp`: `SendTaxiStatus`, which only this class calls, `SendTaxiMenu` and `SendLearnNewTaxiNode`, which the flight master's gossip also calls, and `SendDoFlight` and `SendActivateTaxiReply`, which the player's flight (`entities/player/world/PlayerTaxi.cpp`) calls |

| `social/` | `VoiceChatHandlers` | the client's voice chat opcodes: the voice and microphone switches (`CMSG_VOICE_SESSION_ENABLE`), the active voice channel (`CMSG_SET_ACTIVE_VOICE_CHANNEL`) and a chat channel's voice button (`CMSG_CHANNEL_VOICE_ON`), each read and ignored |

Includes are path-qualified (`#include "session/handlers/combat/CombatHandlers.h"`): this directory is not on the `game` target's include path. `CheckLayout` classifies every file here as session, `CheckHeaderReach` keeps each header that has a rule to forward declarations and the light headers its declarations' types need, and every handler PR adds its header's rule.
