# The opcode handlers (`session/handlers/`)

One directory per domain, one class per origin file in its domain's directory; combat's class, made from two files, and pvp's, the class of both the arena team and the battleground files, are the two exceptions. A handler class is stateless: static entry points only, each `static void HandleX(WorldSession& session, WorldPacket& packet)`, bound by the rows of `Server/OpcodeTable.cpp` through `OpcodeThunk`; status and processing stay table metadata. A handler reaches the session through its public members and borrows it by reference for one call, on the world thread or on the map worker that owns the player's map; `World` owns the sessions and deletes them only between calls. A handler keeps nothing: no data member, no static variable, no session or player pointer in anything that outlives the call. It reads the player through `session.GetPlayer()`, and takes the pointer fresh after any call that can log the player out. Work that finishes later carries the account id and the session id and finds the session again with `WorldSession::FindRequesterSession`, which drops the answer when a reconnect has replaced the session.

| Domain | Class | Handles |
|---|---|---|
| `combat/` | `CombatHandlers` | the client's melee swing, attack stop and sheath (`CMSG_ATTACKSWING`, `CMSG_ATTACKSTOP`, `CMSG_SETSHEATHED`) and duel accept and cancel (`CMSG_DUEL_ACCEPTED`, `CMSG_DUEL_CANCELLED`); `SendAttackStop`, the `SMSG_ATTACKSTOP` the swing sends when it refuses a target, is its private static |
| `economy/` | `AuctionHandlers` | the client's auction house open (`MSG_AUCTION_HELLO`), sale (`CMSG_AUCTION_SELL_ITEM`), bid and buyout (`CMSG_AUCTION_PLACE_BID`), cancel (`CMSG_AUCTION_REMOVE_ITEM`) and its four lists: the search, the player's own auctions, the auctions the player bid on and the pending sales (`CMSG_AUCTION_LIST_ITEMS`, `CMSG_AUCTION_LIST_OWNER_ITEMS`, `CMSG_AUCTION_LIST_BIDDER_ITEMS`, `CMSG_AUCTION_LIST_PENDING_SALES`); `GetCheckedAuctionHouseForAuctioneer`, which finds the auction house an auctioneer's or the player's own guid opens, and `SendAuctionCancelledToBidderMail`, which mails a cancelled auction's bid back to its bidder, are its private statics; the auction senders stay on `WorldSession` in `WorldHandlers/AuctionHouseHandler.cpp`: `SendAuctionHello`, which the auction chat commands and the auctioneer's gossip also call, the bidder and owner notifications and the outbid mail, which the auction house manager also calls, and `SendAuctionCommandResult` and `SendAuctionRemovedNotification`, which only this class calls |
| `economy/` | `LootHandlers` | the client's loot window open and close (`CMSG_LOOT`, `CMSG_LOOT_RELEASE`), item and currency taking (`CMSG_AUTOSTORE_LOOT_ITEM`, `CMSG_LOOT_CURRENCY`, both bound to one static), money taking (`CMSG_LOOT_MONEY`) and the master looter's give (`CMSG_LOOT_MASTER_GIVE`); `DoLootRelease`, which the logout, the logout request and the player's own loot opening (`Player::SendLoot`) also call, stays on `WorldSession` in `WorldHandlers/LootHandler.cpp` |
| `economy/` | `TradeHandlers` | the client's trade request and window open (`CMSG_INITIATE_TRADE`, `CMSG_BEGIN_TRADE`), the notices of a request ignored or met busy (`CMSG_IGNORE_TRADE`, `CMSG_BUSY_TRADE`), the offer's gold, item and item clearing (`CMSG_SET_TRADE_GOLD`, `CMSG_SET_TRADE_ITEM`, `CMSG_CLEAR_TRADE_ITEM`), accept and unaccept (`CMSG_ACCEPT_TRADE`, `CMSG_UNACCEPT_TRADE`) and cancel (`CMSG_CANCEL_TRADE`); `moveItems`, which stores each side's traded items in the other's bags, is its private static; the class is `Player`'s friend for the player's trade data, which the request creates and the completed trade deletes; the trade senders stay on `WorldSession` in `WorldHandlers/TradeHandler.cpp`: `SendTradeStatus` and `SendUpdateTrade`, which the trade data's own members (`TradeData` in `entities/player/Player.cpp`) also call, and `SendCancelTrade`, which `Player::TradeCancel` calls |
| `economy/` | `VendorHandlers` | the client's vendor sell, buyback, buy and inventory list (`CMSG_SELL_ITEM`, `CMSG_BUYBACK_ITEM`, `CMSG_BUY_ITEM`, `CMSG_LIST_INVENTORY`), bag auto-store (`CMSG_AUTOSTORE_BAG_ITEM`) and bank slot purchase and bank auto-store (`CMSG_BUY_BANK_SLOT`, `CMSG_AUTOBANK_ITEM`, `CMSG_AUTOSTORE_BANK_ITEM`); `SendListInventory` and `CheckBanker`, which callers outside the class use, stay on `WorldSession` in `WorldHandlers/ItemHandlerVendor.cpp` |
| `entities/` | `EnchantHandlers` | the client's gift wrapping of an item (`CMSG_WRAP_ITEM`), gem socketing (`CMSG_SOCKET_GEMS`) and the cancelling of a temporary enchantment on an equipped item (`CMSG_CANCEL_TEMP_ENCHANTMENT`); the enchantment senders stay on `WorldSession` in `WorldHandlers/ItemHandlerEnchant.cpp`: `SendEnchantmentLog`, which the item's enchantment change (`Item::SetEnchantment`) calls, and `SendItemEnchantTimeUpdate`, which the player's enchantment durations (`Player::AddEnchantmentDuration`, `Player::SendEnchantmentDurations`) call |
| `entities/` | `SkillHandlers` | the client's talent learning, one rank (`CMSG_LEARN_TALENT`) or the talents chosen in the talent preview as one group (`CMSG_LEARN_TALENT_GROUP`), the talent wipe confirmed at a class trainer (`MSG_TALENT_WIPE_CONFIRM`) and the skill unlearning (`CMSG_UNLEARN_SKILL`) |
| `pvp/` | `PvpHandlers` | the arena team's inspect, query, roster, create, invite, accept, decline, leave, disband, remove and leader opcodes (`MSG_INSPECT_ARENA_TEAMS` and ten `CMSG_ARENA_TEAM_*`); the battlemaster's hello and join, the arena join, the battlefield list, port, leave and status, the flag carriers' positions, the PvP log, the spirit healer's query and queue, the AFK report, and the rated battleground stats, rated battleground info, PvP options and PvP rewards requests (sixteen `CMSG_*` opcodes); `SendArenaTeamCommandResult`, which the arena team's member removal (`ArenaTeam::DelMember`) also calls, and `SendNotInArenaTeamPacket`, which the arena join calls through the player's session, stay on `WorldSession` in `WorldHandlers/ArenaTeamHandler.cpp`, and `SendBattlegGroundList`, which the battlemaster's gossip also calls, in `BattleGround/BattleGroundHandler.cpp` |

Includes are path-qualified (`#include "session/handlers/combat/CombatHandlers.h"`): this directory is not on the `game` target's include path. `CheckLayout` classifies every file here as session, `CheckHeaderReach` keeps each header that has a rule to forward declarations, and every handler PR adds its header's rule, `handler_classes.py` fails on a data member, a non-static member function, a static variable or a base class in any file here, and `handler_verbatim.py` proves each moved body against the `WorldSession` member it was, from the entries in `src/tests/tools/handler_moves.py`, which a handler PR edits and never the tool.
