# The repositories (`persistence/`)

A repository spells the SQL of one table family and reads its rows: the game calls it with plain values and gets plain rows back, so the code that owns the state never names a statement. One directory per database and domain, `persistence/<database>/<domain>/`. A repository includes only the database driver and the foundation (`CheckLayout` classifies every file here as persistence, `src/tests/tools/layout_gate.py`'s `RULES`), so its rows are its own structs and never an entity or a manager.

| Repository | Holds |
|---|---|
| `characters/CharacterTransaction` | `Begin` and `Commit` of a transaction on the character database, for a save whose writes the game issues one repository call at a time (the pet save's spells, cooldowns, auras and row) |
| `characters/inventory/CurrencyRepository` | a character's currency rows (`character_currencies`): `ReadRow` reads one row of the login holder's currency result into a `CurrencyRow` for `CurrencyMgr::LoadRow`; `Update` and `Insert` write the row `CurrencyMgr::Save` hands them for a changed or a new currency; `DeleteEveryRowOf` deletes every character's row of a currency id the load does not know, all queued |
| `characters/pets/PetRepository` | the pets (`character_pet`, `character_pet_declinedname`, `pet_aura`, `pet_spell`, `pet_spell_cooldown`): `PromoteToCurrent` and `Rename` each write one transaction; `Pet::SavePetToDB` opens a `CharacterTransaction` around `_SaveSpells`, `_SaveSpellCooldowns` and `_SaveAuras` (each spell's DELETE and INSERT, the cooldowns' and auras' DELETE and INSERTs, the auras through one statement) and the pet's own DELETE, slot UPDATE, unslotted DELETE and INSERT; `DeleteAllOf` deletes a pet from all five tables; `DeleteSpellOfEveryPet` deletes every pet's row of a spell the spell store does not know, and `DeleteSpellsOfPets` the talent spells of an owner's other pets on a talent reset; the reads are the login holder's pet cache, all writes queued |
| `characters/quests/QuestStatusRepository` | a character's quest status and its weekly and monthly quests (`character_queststatus`, `character_queststatus_weekly`, `character_queststatus_monthly`): `ReadRow` reads one row of the login holder's status result into a `QuestStatusRow` for `QuestStatusMgr::FillRow`, still one row at a time, and `ReadQuestIds` reads a weekly or monthly result's quest ids for `LoadWeekly` and `LoadMonthly`; `QuestStatusMgr::SaveStatus` calls `Insert` or `Update` per new or changed status, and `SaveWeekly` and `SaveMonthly` replace the owner's rows, all queued |
| `characters/social/ArenaTeamRepository` | the arena teams (`arena_team`, `arena_team_member`, `arena_team_stats`): `ReadTeam` and `ReadMember` read one row of the team and member loads for `ArenaTeam`'s two loaders, which keep their loops; `Create`, `Disband` and `SaveStats` each write one transaction, and the member, captain, emblem and single-stat writes are one statement each, all queued |
| `characters/social/ReputationRepository` | a character's reputation rows (`character_reputation`): `ReadRow` reads one row of the login holder's reputation result into a `ReputationRow` for `ReputationMgr::LoadRow`, and `Save` writes the rows `ReputationMgr::SaveToDB` hands it, each a DELETE of the old row and an INSERT of the new one, both queued |
| `characters/social/SocialRepository` | a character's friend and ignore list (`character_social`): `ReadRow` reads one row of the login holder's social result into a `SocialRow` for `PlayerSocial::LoadRow`; `PlayerSocial` calls `AddFlag` or `Insert` when it lists a character, `RemoveFlag` or `Delete` when it takes a flag off, and `SetNote` for a note, all queued |
| `characters/spells/SpellCooldownRepository` | a character's spell cooldowns (`character_spell_cooldown`): `ReadRow` reads one row of the login holder's cooldown result into a `SpellCooldownRow` for `SpellCooldownMgr::LoadRow`; `SpellCooldownMgr::SaveToDB` calls `DeleteAll`, then `Insert` for each cooldown it saves, all queued |
| `characters/talents/GlyphRepository` | a character's glyphs (`character_glyphs`): `ReadRow` reads one row of the login holder's glyph result into a `GlyphRow` for `GlyphMgr::LoadRow`, which deletes an invalid row through `DeleteEveryRowOfGlyph` (every character's rows of an unknown glyph) or `DeleteInvalidRow` (the owner's row of a slot); `GlyphMgr::Save` calls `Insert`, `Update` or `Delete` for each changed slot, all queued |
| `characters/talents/TalentRepository` | a character's talents (`character_talent`): `ReadRow` reads one row of the login holder's talent result into a `TalentRow` for `TalentMgr::LoadRow`, which deletes an invalid row through `DeleteEveryRowOfTalent` or `DeleteEveryRowOfSpec` (every character's rows of an unknown talent or spec) or `DeleteOwnerTalent` or `DeleteOwnerSpec` (the owner's rows); `TalentMgr::SaveTalents` hands `Save` its changed talents in order, each a DELETE of the old row and an INSERT of the new one as its state says, all queued |

Includes are path-qualified (`#include "persistence/characters/social/ReputationRepository.h"`): this directory is not on the `game` target's include path. Every file here is on `CheckSyncDb`'s list, and each table is in its owner's `CheckStateOwnership` row, with the repository's file allowed to spell it.
