# The repositories (`persistence/`)

A repository spells the SQL of one table family and reads its rows: the game calls it with plain values and gets plain rows back, so the code that owns the state never names a statement. One directory per database and domain, `persistence/<database>/<domain>/`. A repository includes only the database driver and the foundation (`CheckLayout` classifies every file here as persistence, `src/tests/tools/layout_gate.py`'s `RULES`), so its rows are its own structs and never an entity or a manager. RowReader.h reads a result into those structs: `ReadRows` every row in order and `ReadRow` the first, each through the repository's reader of the row's columns, so the caller never sees a column position. `ReadWorldTable` reads a whole world table for a loader: when the select answers no row it counts the rows of the same select (`SELECT COUNT(*) FROM (<select>) AS probe`), so the `TableRead` it answers (`TableRead.h`, no driver types) tells loaded rows, an empty table, a failed query and a table that changed during the read apart.
