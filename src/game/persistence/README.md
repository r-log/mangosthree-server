# The repositories (`persistence/`)

A repository spells the SQL of one table family and reads its rows: the game calls it with plain values and gets plain rows back, so the code that owns the state never names a statement. One directory per database and domain, `persistence/<database>/<domain>/`. A repository includes only the database driver and the foundation (`CheckLayout` classifies every file here as persistence, `src/tests/tools/layout_gate.py`'s `RULES`), so its rows are its own structs and never an entity or a manager.

| Repository | Holds |
|---|---|
| `characters/CharacterDeleteRepository` | a character's delete: `QueueDeleteReads` asks, in one holder, for the reads the delete needs (the group and petition signatures always, and for a full delete the COD mails, their items, the pets and who lists the character), with the delete request's ownership read when asked, the slots in the header; `DeleteEveryRowOf` deletes the 33 tables' rows inside the `CharacterTransaction` the delete opens, `MarkDeleted` is the soft delete, and `QueryDeletedBefore` asks for the soft-deleted characters the purge removes, all writes queued |
| `characters/CharacterRepository` | a character's own rows as the character screen and the login read them (`characters`, `character_declinedname`): every read is asynchronous, the character list (`QueryEnum`), the create's two holders (the account's count on the login database, then the realm's three reads) and the customize holder, with their slots in the header; `StageLoginReads` fills the login holder, one read per `PlayerLoginQueryIndex` slot, and `QueueLoginReads` queues it; the name query's `QueryName`, the rename read and `Rename`, which joins the `CharacterTransaction` the rename handler opens; `SetDeclinedNames` writes one transaction, and a reorder's `SetSlot` calls join the handler's transaction; `SetOnline` marks a character online and `SetAccountOffline` every character of an account at logout, all writes queued; `QueryAccountCharacters` and `QueryAccountCharacterCount` run the account manager's reads, synchronously |
| `characters/CharacterSaveRepository` | a character's save (`characters`, `character_action`, `character_aura`, `character_cuf_profiles`, `character_skills`, `character_spell`, `character_stats`, `character_equipmentsets`, `character_battleground_data`): `Player::SaveToDB` opens a `CharacterTransaction` around `ReplaceCharacter` (the old row's DELETE, then the INSERT of the `CharacterSaveRow` it fills) and the save of every table it owns; the actions, skills, spells and equipment sets are one statement per changed row, the auras, raid-frame profiles, stats and battleground return point a DELETE and the INSERTs of the rows handed; `SetMoney` saves the money alone and `SetPosition` an offline character's position, all queued |
| `characters/CharacterTransaction` | `Begin`, `Commit` and `Rollback` of a transaction on the character database, for a save whose writes the game issues one repository call at a time (the pet save's spells, cooldowns, auras and row) |
| `characters/account/AccountDataRepository` | the client's saved settings (`account_data`, `character_account_data`, `character_tutorial`): `QueryGlobal` and `QueryTutorials` run when a session is attached, synchronously, for `WorldSession`'s loaders, which keep their loops; `ReplaceGlobal` and `ReplaceCharacter` each write one transaction (the old block's DELETE, the new one's INSERT), and `UpdateTutorials` or `InsertTutorials` saves the flags, and `DeleteTutorials` deletes them with the account, all queued |
| `characters/achievements/AchievementRepository` | the characters' achievements (`character_achievement`, `character_achievement_progress`): `QueryCompletedAchievements` and `QueryProgressCriteria` run the startup cleanup's reads, synchronously; `AchievementMgr::SaveToDB` calls `ReplaceCompleted` per changed achievement and `DeleteProgress` and `InsertProgress` per changed criteria; `DeleteAllOf` writes one transaction, and `DeleteAchievementOfEveryCharacter` and `DeleteCriteriaOfEveryCharacter` drop what the stores do not know, all queued |
| `characters/economy/AuctionRepository` | the auctions (`auction`): `QueryAuctionItems`, `QueryAuctionCount` and `QueryAuctions` run the startup loads, synchronously, and `ReadAuction` reads one auction for `AuctionHouseMgr::LoadAuctions`, which fixes an auction's item data through `SetItemData`; a new auction's `Insert` and the bid and win updates join the `CharacterTransaction` the auction code opens around them and the player's save, and `Delete` is one statement, all queued. A won or returned auction's item goes through the mail repository's item writes |
| `characters/inventory/CurrencyRepository` | a character's currency rows (`character_currencies`): `ReadRow` reads one row of the login holder's currency result into a `CurrencyRow` for `CurrencyMgr::LoadRow`; `Update` and `Insert` write the row `CurrencyMgr::Save` hands them for a changed or a new currency; `DeleteEveryRowOf` deletes every character's row of a currency id the load does not know, all queued |
| `characters/inventory/ItemRepository` | the items (`item_instance`, `character_gifts`, `item_loot`, and an item's `character_inventory` row): `QueryGift` asks, asynchronously, for a wrapped item's gift row, and `InsertGift` writes one inside the transaction the wrap opens; the character's save writes its inventory rows through `InsertInventoryRow`, `UpdateInventoryRow` and `DeleteInventoryRow`; `Item::SaveToDB` calls `DeleteInstance` and `InsertInstance` for a new item, `UpdateInstance` and `SetGiftOwner` for a changed one, `DeleteInstance`, `DeleteGift` and `DeleteLoot` for a removed one, then `DeleteLoot`, `InsertLootMoney` and `InsertLootItems` (one statement for every loot row) for its saved loot; the load's fixes go through `DeleteGift`, `UpdateInstanceData`, `DeleteLootItem` and `DeleteLootCurrency`, and a character's delete drops an item without a template through `DeleteUnknownItem`, all queued |
| `characters/mail/MailRepository` | the mails (`mail`, `mail_items`) and the mail flow's item instance writes: `MailDraft::SendMailTo` opens a `CharacterTransaction` around `InsertMail` (subject and body bound) and an `InsertMailItem` per item, `Mail::prepareTemplateItems` one around `SetHasItems` and the generated items' saves and rows, and the send, return and take handlers one around the item and player saves they call, with `SetMailedItemOwner` for each mailed item; `DeleteMail` writes one transaction, and `DeleteMailRow` and `DeleteMailItems` are its two halves, as a character's delete returns or drops its COD mails; the receiver's save writes `UpdateState`, `DeleteTakenItems` and `DeleteDeletedMail` and `DeleteDroppedItem` deletes a dropped draft's item; `QueryMailboxCount` and `QueryMassMailReceivers` are asynchronous reads whose callbacks get the result, all writes queued |
| `characters/maps/CorpseRepository` | the players' corpses (`corpse`): a corpse's save opens a `CharacterTransaction` around `DeleteOfPlayer` (the player's corpses that are not bones) and `Insert` (the `CorpseRow` it fills, written as the stream prints it), all queued |
| `characters/maps/InstanceBindRepository` | a character's instance binds (`character_instance`, and their copy to `group_instance`): `InsertBind`, `UpdateBind` and `DeleteBind` as a character binds, rebinds and unbinds, and the load drops a bind it cannot use; `CopyBindsToGroup` and `DeleteTemporaryBinds` when the character's binds become its group's, all queued |
| `characters/pets/PetRepository` | the pets (`character_pet`, `character_pet_declinedname`, `pet_aura`, `pet_spell`, `pet_spell_cooldown`): `PromoteToCurrent` and `Rename` each write one transaction; `Pet::SavePetToDB` opens a `CharacterTransaction` around `_SaveSpells`, `_SaveSpellCooldowns` and `_SaveAuras` (each spell's DELETE and INSERT, the cooldowns' and auras' DELETE and INSERTs, the auras through one statement) and the pet's own DELETE, slot UPDATE, unslotted DELETE and INSERT; `DeleteAllOf` deletes a pet from all five tables; `DeleteSpellOfEveryPet` deletes every pet's row of a spell the spell store does not know, and `DeleteSpellsOfPets` the talent spells of an owner's other pets on a talent reset; `ReplaceStarterPet` writes a new warlock's or hunter's first pet; `SetStableSlot` moves a pet in a stable swap, both writes inside the stable handler's `CharacterTransaction`; the reads are the login holder's pet cache, all writes queued |
| `characters/quests/QuestStatusRepository` | a character's quest status and its weekly and monthly quests (`character_queststatus`, `character_queststatus_weekly`, `character_queststatus_monthly`): `ReadRow` reads one row of the login holder's status result into a `QuestStatusRow` for `QuestStatusMgr::FillRow`, still one row at a time, and `ReadQuestIds` reads a weekly or monthly result's quest ids for `LoadWeekly` and `LoadMonthly`; `QuestStatusMgr::SaveStatus` calls `Insert` or `Update` per new or changed status, and `SaveWeekly`, `SaveMonthly` and `SaveDaily` replace the owner's rows, all queued |
| `characters/quests/QuestTrackerRepository` | the quest tracker (`quest_tracker`), written when the tracker is enabled: `InsertAccept` records an acceptance with the core's hash and revision, and `SetCompleteTime`, `SetAbandonTime` and `SetCompletedByGm` stamp the latest acceptance, all queued |
| `characters/social/ArenaTeamRepository` | the arena teams (`arena_team`, `arena_team_member`, `arena_team_stats`): `ReadTeam` and `ReadMember` read one row of the team and member loads for `ArenaTeam`'s two loaders, which keep their loops; `Create`, `Disband` and `SaveStats` each write one transaction, and the member, captain, emblem and single-stat writes are one statement each, all queued |
| `characters/social/CalendarRepository` | the calendar (`calendar_events`, `calendar_invites`): `QueryEvents` and `QueryInvites` run the startup loads, synchronously, `ReadEvent` and `ReadInvite` read one row each for `CalendarMgr::LoadCalendarsFromDB`, which keeps its loops and empties a table through `TruncateEvents` or `TruncateInvites` as before; the event and invite writes (insert, update, delete, reply, status, rank) are one statement each, all queued |
| `characters/social/GroupRepository` | the groups (`groups`, `group_member`, `group_instance`): `Group::Create` opens a `CharacterTransaction` around `Store` (the leftover rows deleted, the group's row inserted) and its first member's `InsertMember`, and `Group::_setLeader` one around the replaced binds' DELETE, `MoveBindsToLeader`, the new leader's binds and `SetLeader`; `Disband` writes one transaction; the member, type, difficulty, main tank and assistant writes and the instance binds are one statement each (`ConvertToParty` two), all queued |
| `characters/social/GuildBankRepository` | the guild banks (`guild_bank_tab`, `guild_bank_item`, `guild_bank_right`, `guild_bank_eventlog`, and the bank columns of `guild` and `guild_member`): `QueryTabs`, `QueryItems` and `QueryEventLog` run the startup loads, synchronously, for loaders that keep their loops; `CreateTab` writes one transaction; every item move opens a `CharacterTransaction` around its event log rows, slot rows, item saves and the player's save; the money, daily allowance, right and tab writes are one call each, the strings bound, all queued |
| `characters/social/GuildRepository` | the guilds (`guild`, `guild_member`, `guild_rank`, `guild_bank_right`, `guild_eventlog`, and the bank tables a disband deletes): `QueryGuilds`, `QueryRanks`, `QueryMembers`, `QueryBankRights` and `QueryEventLog` run the startup loads, synchronously, for loaders that keep their loops; `Create` and `DeleteRank` each write one transaction; a rank switch, the broken-rank repair and a disband open a `CharacterTransaction` around their writes and the member or bank item writes they call; the guild, member, rank and event log writes are one statement each, the strings bound except in a rank switch's `ReplaceRank`, all queued |
| `characters/social/PetitionRepository` | the guild charters (`petition`, `petition_sign`): every read is asynchronous, four single reads and three holders (show or offer, the sign request, the turn-in) with their slots in the header, and `QueueSign` the atomic sign; a new charter (`GuidList` builds the list its write deletes) and a petition's delete each write one transaction, and a rename is one statement, the strings bound; `QuerySignaturesBy`, `DeleteSignaturesBy` and `DeleteOwnedBy` (one transaction) clear a character's signatures and charters when it joins a guild or is deleted, all queued |
| `characters/social/ReputationRepository` | a character's reputation rows (`character_reputation`): `ReadRow` reads one row of the login holder's reputation result into a `ReputationRow` for `ReputationMgr::LoadRow`, and `Save` writes the rows `ReputationMgr::SaveToDB` hands it, each a DELETE of the old row and an INSERT of the new one, both queued |
| `characters/social/SocialRepository` | a character's friend and ignore list (`character_social`): `ReadRow` reads one row of the login holder's social result into a `SocialRow` for `PlayerSocial::LoadRow`; `PlayerSocial` calls `AddFlag` or `Insert` when it lists a character, `RemoveFlag` or `Delete` when it takes a flag off, and `SetNote` for a note, all queued; `QueryFlags` asks, asynchronously, for an offline character's flags for another, as the calendar invite does |
| `characters/social/TicketRepository` | the GM tickets, surveys and bug reports (`character_ticket`, `gm_surveys`, `bugreport`): `ReadHighestTicketId`, `ReadAutoIncrementNext` and `QueryOpenTickets` run the startup loads, synchronously, and `ReadTicket` reads one open ticket for `GMTicketMgr::LoadGMTickets`; the new ticket (with its id), the text, the response, the resolve, the delete of every ticket, the delete of a character's open tickets, the survey and a bug report are one statement each, the strings bound, all queued |
| `characters/spells/SpellCooldownRepository` | a character's spell cooldowns (`character_spell_cooldown`): `ReadRow` reads one row of the login holder's cooldown result into a `SpellCooldownRow` for `SpellCooldownMgr::LoadRow`; `SpellCooldownMgr::SaveToDB` calls `DeleteAll`, then `Insert` for each cooldown it saves, all queued |
| `characters/talents/GlyphRepository` | a character's glyphs (`character_glyphs`): `ReadRow` reads one row of the login holder's glyph result into a `GlyphRow` for `GlyphMgr::LoadRow`, which deletes an invalid row through `DeleteEveryRowOfGlyph` (every character's rows of an unknown glyph) or `DeleteInvalidRow` (the owner's row of a slot); `GlyphMgr::Save` calls `Insert`, `Update` or `Delete` for each changed slot, all queued |
| `characters/talents/TalentRepository` | a character's talents (`character_talent`): `ReadRow` reads one row of the login holder's talent result into a `TalentRow` for `TalentMgr::LoadRow`, which deletes an invalid row through `DeleteEveryRowOfTalent` or `DeleteEveryRowOfSpec` (every character's rows of an unknown talent or spec) or `DeleteOwnerTalent` or `DeleteOwnerSpec` (the owner's rows); `TalentMgr::SaveTalents` hands `Save` its changed talents in order, each a DELETE of the old row and an INSERT of the new one as its state says, all queued |
| `login/AccountRepository` | the accounts on the login database (`account`, `account_banned`, `ip_banned`, `realmcharacters`): `RegisterThread` registers a network thread with the client library before it reads, and `QueryAuthAccount` (the name escaped) and `QueryActiveBan` run the authentication reads on that thread, synchronously; `SetLastIp` records an authenticated login's address; the account manager's `QueryExists`, `QueryIdByName` (the name escaped), `QueryGmLevel` and `QueryName` read on its caller's thread, synchronously, and its `Insert`, `InsertWithExpansion`, `LinkNewAccountsToRealms`, `SetNameAndPasswordHash` (the name escaped), `SetPasswordHash` and `Delete` (one transaction) are queued, `QueryNameAndPasswordHash` asking asynchronously for the password check; `QueryGmLevel` asks, asynchronously, for an account's GM level, as an auction won by an offline bidder does for its gm.log line, and `QueryWhois` for an account's name, email and last IP; `SetActiveRealm` sets the realm an account plays on at login and clears it at logout, and `SetRealmCharacterCount` rewrites its character count on a realm after a create, all writes queued |
| `login/RealmRepository` | the realm list on the login database (`realmlist`): `SetPopulation` writes the population a session's arrival leaves, queued |
| `world/achievements/AchievementDataRepository` | the achievement data on the world database (`achievement_criteria_requirement`, `achievement_reward`, `locales_achievement_reward`): three loads at startup and on a reload, synchronously, for loaders that keep their loops |
| `world/spawns/SpawnRepository` | the creature and game object spawns on the world database (`creature`, `gameobject`, and the tables keyed on a spawn): a GM's save of a spawn is one transaction (`ReplaceCreature` or `ReplaceGameObject`: the old row's DELETE, then the INSERT of the row it fills, written as the stream prints it), a creature's delete one transaction of seven DELETEs and a game object's three DELETEs, all queued and written to the SQL log |

Includes are path-qualified (`#include "persistence/characters/social/ReputationRepository.h"`): this directory is not on the `game` target's include path. Every file here is on `CheckSyncDb`'s list, and each table is in its owner's `CheckStateOwnership` row, with the repository's file allowed to spell it.
