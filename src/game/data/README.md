# The data stores (`data/`)

The stores here hold world data loaded once from the world database at start-up (and again on a `.reload`, for a table that has one) and then only read, through lookups. A store is the container and its lookups: it names no entity, session, packet or database type, so the stores build and are tested in `mangos_tests` with no database. The loader that reads the table and validates its rows stays with `ObjectMgr` until the loaders move; `ObjectMgr` owns each store and its getter forwards to the lookup.

| Store | Holds |
|---|---|
| `MailLevelRewardStore` | the mail a character is sent on reaching a level (`mail_level_reward`): per level, the rewards in the order loaded, each for the races in its mask; `ObjectMgr::LoadMailLevelRewards` fills it and `ObjectMgr::GetMailLevelReward` forwards to its lookup |
| `FishingBaseSkillStore` | the base fishing skill level of an area (`skill_fishing_base_level`): one value per area id, which may be negative, a second value for an area overwriting the first; `ObjectMgr::LoadFishingBaseSkillLevel` clears and fills it (at start-up, and on `.reload skill_fishing_base_level` or `.reload all`) and `ObjectMgr::GetFishingBaseSkillLevel` forwards to its lookup |
| `ExplorationBaseXpStore` | the base XP of exploring an area of a given level (`exploration_basexp`): one value per area level, a second value for a level overwriting the first; `ObjectMgr::LoadExplorationBaseXP` fills it at start-up only (no `.reload` reads the table) and `ObjectMgr::GetBaseXP` forwards to its lookup |
| `PointOfInterestStore` | the points of interest (`points_of_interest`): the map pins a gossip menu can show, one per id, a second point for an id overwriting the first; `ObjectMgr::LoadPointsOfInterest` clears and fills it (at start-up, and on `.reload points_of_interest` or `.reload all`) and `ObjectMgr::GetPointOfInterest` forwards to its lookup; the point names per locale stay with the locales |
| `QuestPOIStore` | the quest points of interest (`quest_poi`, with their points from `quest_poi_points`): per quest, the POIs in the order loaded, each holding its points; `ObjectMgr::LoadQuestPOI` clears and fills it (at start-up, and on `.reload quest_poi` or `.reload all`), adds each point to its POI through the store's edit access, which leaves an empty entry for a quest only the points table names, and `ObjectMgr::GetQuestPOIVector` forwards to its lookup |
| `DungeonFinderStore` | the dungeon finder's data: the requirements to enter a dungeon at a difficulty (`dungeonfinder_requirements`, one entry per map and difficulty), the base XP and money rewards per level (`dungeonfinder_rewards`) and the item rewards per id (`dungeonfinder_item_rewards`), a second entry for a key overwriting the first; `ObjectMgr::LoadDungeonFinderRequirements`, `ObjectMgr::LoadDungeonFinderRewards` and `ObjectMgr::LoadDungeonFinderItems` each clear and fill their own map at start-up only (no `.reload` reads the three tables), and `ObjectMgr::GetDungeonFinderRequirements`, `ObjectMgr::GetDungeonFinderRewards` and the three whole-map getters forward to it; the dungeon entrances (`lfg_dungeon_entrances`) are held in `ObjectMgr` (`ObjectMgr::GetLfgDungeonEntrance`) |

Includes are path-qualified (`#include "data/MailLevelRewardStore.h"`): this directory is not on the `game` target's include path. `CheckLayout` classifies every file here as data (`src/tests/tools/layout_gate.py`'s `RULES`), and `CheckHeaderReach` keeps each store's header from reaching `ObjectMgr.h`, the entities, the session, the world, the database and the packets.
