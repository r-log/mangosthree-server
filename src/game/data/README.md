# The data stores (`data/`)

The stores here hold world data loaded once from the world database at start-up (and again on a `.reload`, for a table that has one) and then only read, through lookups. A store is the container and its lookups: it names no entity, session, packet or database type, so the stores build and are tested in `mangos_tests` with no database. The loader that reads the table and validates its rows stays with `ObjectMgr` until the loaders move; `ObjectMgr` owns each store and its getter forwards to the lookup, except the two script stores, which are reached through their own accessors and filled by `ScriptMgr`'s loaders.

| Store | Holds |
|---|---|
| `MailLevelRewardStore` | the mail a character is sent on reaching a level (`mail_level_reward`): per level, the rewards in the order loaded, each for the races in its mask; `ObjectMgr::LoadMailLevelRewards` clears and fills it (at start-up, and on `.reload mail_level_reward` or `.reload all`) and `ObjectMgr::GetMailLevelReward` forwards to its lookup |
| `FishingBaseSkillStore` | the base fishing skill level of an area (`skill_fishing_base_level`): one value per area id, which may be negative, a second value for an area overwriting the first; `ObjectMgr::LoadFishingBaseSkillLevel` clears and fills it (at start-up, and on `.reload skill_fishing_base_level` or `.reload all`) and `ObjectMgr::GetFishingBaseSkillLevel` forwards to its lookup |
| `ExplorationBaseXpStore` | the base XP of exploring an area of a given level (`exploration_basexp`): one value per area level, a second value for a level overwriting the first; `ObjectMgr::LoadExplorationBaseXP` fills it at start-up only (no `.reload` reads the table) and `ObjectMgr::GetBaseXP` forwards to its lookup |
| `MapGeometry` | not a store: a map's grid and cell geometry (the grid and cell sizes and counts, `GridPair` and `CellPair`, the grid or cell a position falls in) and the validity checks: a coordinate (`MaNGOS::IsValidMapCoord`), a map id the server can load (`MaNGOS::IsValidMapId`: in Map.dbc, and a dungeon only with an instance template) and a position on such a map (`MaNGOS::IsValidMapPosition`); the loaders check their rows with it, and `GridDefines.h` and `MapManager`'s checks build on it |
| `PointOfInterestStore` | the points of interest (`points_of_interest`): the map pins a gossip menu can show, one per id, a second point for an id overwriting the first; `ObjectMgr::LoadPointsOfInterest` clears and fills it (at start-up, and on `.reload points_of_interest`, `.reload all_npc`, `.reload all_gossips` or `.reload all`) and `ObjectMgr::GetPointOfInterest` forwards to its lookup; the point names per locale stay with the locales |
| `PageTextStore` | the page texts (`page_text`): the pages of a book, letter or plaque, one per id, each naming the page after it, the store owning each page's text, a second page for an id overwriting the first; `ObjectMgr::LoadPageTexts` reads the rows through `PageTextRepository`, clears and fills it (at start-up, and on `.reload page_text`, `.reload all_item` or `.reload all`), keeps the pages it holds when the table is empty, stops the server when the table cannot be read at start-up, then cuts a circular chain of pages through the store's edit access; `ObjectMgr::ReloadPageTexts` does the same on a reload but keeps the pages it holds when the table cannot be read and answers how the read ended, which `.reload page_text` reports; `ObjectMgr::GetPageText` forwards to its lookup |
| `QuestPOIStore` | the quest points of interest (`quest_poi`, with their points from `quest_poi_points`): per quest, the POIs in the order loaded, each holding its points; `ObjectMgr::LoadQuestPOI` clears and fills it (at start-up, and on `.reload quest_poi`, `.reload all_quest` or `.reload all`), adds each point to its POI through the store's edit access, which leaves an empty entry for a quest only the points table names, and `ObjectMgr::GetQuestPOIVector` forwards to its lookup |
| `CreatureAddonStore` | the creature addons, one store per table (`creature_addon` by spawn guid, `creature_template_addon` by creature entry): the mount, bytes, sheath and PvP states, emote and move flags per key, and the aura list the store owns, 0 terminated or NULL; `ObjectMgr::LoadCreatureAddons` reads both tables through `CreatureAddonRepository` at start-up only (no `.reload` reads them), stops the server when a table cannot be read, checks each addon in ascending key order from 1 (an unknown mount or emote set to 0 through the store's edit access) and turns its aura text into the list, then reports a key whose creature entry or spawn does not exist; the static `ObjectMgr::GetCreatureAddon` and `ObjectMgr::GetCreatureTemplateAddon` forward to the lookups |
| `CreatureEquipmentStore` | the creature equipment templates (`creature_equip_template`): one per equipment id, the main hand, off-hand and ranged items, a second template for an id overwriting the first; `ObjectMgr::LoadEquipmentTemplates` reads the rows through `CreatureEquipmentRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then sets to 0 an item that `Item.dbc` does not hold or that cannot be held in a hand, through the store's edit access, and the static `ObjectMgr::GetEquipmentInfo` forwards to its lookup |
| `CreatureModelInfoStore` | the creature model infos (`creature_model_info`), a `KeyedRecordStore` of `CreatureModelInfo` by display id: the bounding radius, combat reach, gender and the other-gender and alternative display ids; `ObjectMgr::LoadCreatureModelInfo` reads the rows through `CreatureModelInfoRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks each model in ascending order from 1 and each playable race's two models, fixing a bad gender, a redundant or unknown other-gender or alternative id, a bounding radius at or below 0 and a combat reach other than 1.5 through the store's edit access, and the static `ObjectMgr::GetCreatureModelInfo` forwards to its lookup |
| `DungeonFinderStore` | the dungeon finder's data: the requirements to enter a dungeon at a difficulty (`dungeonfinder_requirements`, one entry per map and difficulty), the base XP and money rewards per level (`dungeonfinder_rewards`) and the item rewards per id (`dungeonfinder_item_rewards`), a second entry for a key overwriting the first; `ObjectMgr::LoadDungeonFinderRequirements`, `ObjectMgr::LoadDungeonFinderRewards` and `ObjectMgr::LoadDungeonFinderItems` each clear and fill their own map at start-up only (no `.reload` reads the three tables), and `ObjectMgr::GetDungeonFinderRequirements`, `ObjectMgr::GetDungeonFinderRewards` and `ObjectMgr::GetDungeonFinderItemsMap` forward to it; the dungeon entrances (`lfg_dungeon_entrances`) are held in `LfgDungeonEntranceStore` |
| `GameObjectTemplateStore` | the game object templates (`gameobject_template`): one `GameObjectInfo` per entry, moved here from `GameObject.h` with its type-specific data unions and helpers, the store owning its four texts; `ObjectMgr::LoadGameobjectInfo` reads the rows through `GameObjectTemplateRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks every row read, in that order, fixing a size at or below 0, a chair height out of range and a capture point's minimum time of 0 through the store's edit access; the static `ObjectMgr::GetGameObjectInfo` forwards to its lookup, and `ObjectMgr::GetGameObjectTemplates` hands the store to the readers that walk every template in ascending entry order (the gossip, loot and quest checks, the script event ids and `.lookup object`) |
| `InstanceTemplateStore` | the instance templates (`instance_template`): one per instance map, its parent map and its level range, a second template for a map overwriting the first; `ObjectMgr::LoadInstanceTemplate` reads the rows through `InstanceTemplateRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then erases a template whose map is unknown or not instanceable and clears a parent that is unknown or a continent through the store's edit access, and the static `ObjectMgr::GetInstanceTemplate` forwards to its lookup |
| `KeyedRecordStore` | the shared store of records held one to a key (`KeyedRecordStore.h`, a template) for a record type it need not know: lookups by key, a loader's edit access, erase, clear and the highest key; `ObjectMgr` holds the conditions (`conditions`) in one, over `PlayerCondition`, which keeps its checks and its evaluation in `ObjectMgr.h`; `ObjectMgr::LoadConditions` reads the rows through `ConditionRepository` and fills it at start-up, stopping the server when the table cannot be read, `ObjectMgr::ReloadConditions` does the same on `.reload conditions` but keeps the conditions it holds when the table cannot be read and answers how the read ended, which the command reports; both then check the conditions in ascending order, erasing an invalid one, and `ObjectMgr::GetCondition` forwards to its lookup; `ObjectMgr` also holds the creature template spells (`creature_template_spells`) in one, over `CreatureTemplateSpells` (in `CreatureRecords.h`): `ObjectMgr::LoadCreatureTemplateSpells` reads the rows through `CreatureTemplateSpellsRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks every row read, in that order, erasing the spells of an unknown creature and setting an unknown spell to 0, and the static `ObjectMgr::GetCreatureTemplateSpells` forwards to its lookup; `ObjectMgr` also holds the creature templates (`creature_template`) in one, over `CreatureInfo` (in `CreatureRecords.h`), the four texts each template points at held in a `TextPool`: `ObjectMgr::LoadCreatureTemplates` reads the rows through `CreatureTemplateRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks each template in ascending entry order from 1 and fixes a bad value through the store's edit access, as `ObjectMgr::LoadNPCSpellClickSpells` does to mark a template spell-clickable; the static `ObjectMgr::GetCreatureTemplate` forwards to its lookup, and `ObjectMgr::GetCreatureTemplates` hands the store to the readers that walk every entry; `ObjectMgr` also holds the item prototypes (`item_template`) in one, over `ItemPrototype`, which stays in `ItemPrototype.h` with the item enums its readers include it for, the name and description each prototype points at held in a `TextPool`: `ObjectMgr::LoadItemPrototypes` reads the rows through `ItemTemplateRepository` at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, fills the store with `ObjectMgr::FillItemPrototypes` (which the tests' item fixture runs on its own rows), then checks each prototype in ascending entry order from 1 and fixes a bad value through the store's edit access; the static `ObjectMgr::GetItemPrototype` forwards to its lookup, and `ObjectMgr::GetItemPrototypes` hands the store to the readers that walk every entry; `ObjectMgr` also holds the game object addons (`gameobject_addon`) in one, over `GameObjectDataAddon` (in `GameObjectRecords.h`): `ObjectMgr::LoadGameObjectAddon` reads the rows through `GameObjectAddonRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks each addon in ascending spawn guid order from 1, logging one whose game object does not exist and resetting a path rotation that is not a unit quaternion to (0, 0, 0, 1) through the store's edit access, and the static `ObjectMgr::GetGameObjectAddon` forwards to its lookup for the game object's creation |
| `LfgDungeonEntranceStore` | the LFG dungeon entrances (`lfg_dungeon_entrances`): the entrance position override per dungeon id, read by the dungeon finder's teleport, a second entrance for a dungeon overwriting the first; `ObjectMgr::LoadLfgDungeonEntrances` clears and fills it at start-up only (no `.reload` reads the table), skipping a row whose dungeon is not in `LFGDungeons.dbc`, and `ObjectMgr::GetLfgDungeonEntrance` forwards to its lookup |
| `MultiRecordStore` | the shared store of records held several to a key (`MultiRecordStore.h`, a template): each key's records in the order added, handed out as a pair of iterators that read a record with `->`, a key erased with all its records; `VehicleAccessoryStore` and `SpellScriptTargetStore` are two |
| `ServerSpellStore` | the server-side spells (`spell_template`): spells the client's spell data does not hold, one per id, each with its main record, its one effect and its aura options, named in every locale by its comment; the store owns the records and the name, which keep their addresses while it lives, and builds the main record in place, as `SpellEntry` cannot be constructed or copied. `ObjectMgr::LoadSpellTemplate` reads the rows through `SpellTemplateRepository` at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, adds each spell zeroed and fills it with `ObjectMgr::FillServerSpell` (the columns into the fields they name, every other field 0, no effect when its aura needs base points, which the table does not hold) and points the spell stores at them: the spell store at its id, the effect map at its effect and the aura options store, past its last row, at its aura options. It refuses a spell `Spell.dbc` holds, keeping the DBC spell, and an id past the spell store's last row |
| `SpellScriptTargetStore` | the spell script targets (`spell_script_target`): the creatures and game objects a scripted spell may target, per spell, in the order loaded; `SpellMgr::LoadSpellScriptTarget` reads the rows through `SpellScriptTargetRepository` and fills it at start-up, stopping the server when the table cannot be read; `SpellMgr::ReloadSpellScriptTarget` does the same on `.reload spell_script_target` or `.reload all_spell` but keeps the targets it holds when the table cannot be read and answers how the read ended, which the command reports; both then check every row read, in that order, erasing every target of a spell with a bad row, and `SpellMgr::GetSpellScriptTargets` forwards to its lookup for the spell targeting and checks |
| `CreatureRecords` | not a store: the creature records `ObjectMgr` holds and the vocabulary of their columns, which `Creature.h` includes: the templates (`CreatureInfo`, with the extra flags, movement, inhabit and regeneration values), the template spells, the spawns (`CreatureData`), the class level stats, the model races, the creature, gossip option and point of interest locales, the vendor items (`VendorItemData`) and the trainer spells (`TrainerSpellData`) |
| `GameObjectRecords` | not a store: the game object records `ObjectMgr` holds, which `GameObject.h` includes: the spawns (`GameObjectData`), the addons (`GameObjectDataAddon`), their rotation type (`QuaternionData`), the show states (`GOState`) and the game object locales |
| `GossipRecords` | not a store: the npc texts (`GossipText`, `npc_text`), their locales and the page text locales, which `ObjectMgr` holds, and the gossip vocabulary of the gossip menu options and points of interest (`Gossip_Option`, `GossipOptionIcon`, `Poi_Icon`); `GossipDef.h` includes it |
| `PlayerCreateInfo` | not a store: the player create info `ObjectMgr` holds (`PlayerInfo`, `playercreateinfo` and its item, spell and action lists), the level stats (`PlayerLevelInfo`) and the action bar's vocabulary (the button types, the totem bar, the limits); `IsActionButtonDataValid` checks a button, for `ObjectMgr::LoadPlayerInfo`'s `playercreateinfo_action` rows with no owner and for a player with its name and the spells it knows (`ActionButtonOwner`); `Player.h` includes it |
| `ArenaSlots` | not a store: the arena team slots of a character, one per arena type (`MAX_ARENA_SLOT`), and the slot of each type and the type of each slot (`GetArenaSlotByType`, `GetArenaTypeBySlot`), which `ArenaTeam` and `CharacterCache` read |
| `ReputationRecords` | not a store: the reputation records `ObjectMgr` holds: the spillover templates (`RepSpilloverTemplate`), which `ReputationMgr` reads, the reward rates and the reputation on kill |
| `CellObjectGuids` | not a store: the spawn guids `ObjectMgr` files under each grid cell of a map and spawn mode, creatures, game objects and corpses (`MapObjectGuids`), and the guid set of one kind (`CellGuidSet`), which `MapPersistentStateMgr.h` uses for its own per-cell copy |
| `TextPool` | the texts a store's records point at, each a copy that keeps its address until the pool is cleared; `ObjectMgr` holds the creature templates' texts in one and the item prototypes' in another |
| `VehicleAccessoryStore` | the vehicle accessories (`vehicle_accessory`): the passengers boarded onto a vehicle, per vehicle entry, in the order loaded; `ObjectMgr::LoadVehicleAccessory` reads the rows through `VehicleAccessoryRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks every row read, in that order, and erases every passenger of a vehicle whose vehicle or passenger entry is unknown or whose seat is out of range; `ObjectMgr::GetVehicleAccessories` forwards to its lookup, which `VehicleInfo::Initialize` walks to board them |
| `GameConfig` | the server configuration values from `mangosd.conf`, read through `sGameConfig`: `World::LoadConfigSettings` sets them at start-up and on `.reload config` (`ServerControl::ReloadConfig`), and `World`'s `getConfig`, `setConfig`, `IsPvPRealm`, `IsFFAPvPRealm`, `GetConfigMaxSkillValue`, `GetDefaultDbcLocale` and `GetAvailableDbcLocale` forward to it; `World` also sets the DBC locale. The visibility distances, the relocation limits and the observer sweep settings are static, set by `World::LoadConfigSettings` and read through `GameConfig::Get...()`. It also holds the visibility distance constants, the `RealmZone` values and the `realmID` declaration |
| `DbScriptStore` | the database scripts (`db_scripts`), with the step and command types of a script (`ScriptInfo`, `DBScriptType`, `DBScriptCommand`): per type, the chains of steps by script id, each in the order loaded, read through `sDbScriptStore`; `ScriptMgr::LoadDbScripts` fills a type's chains under the store's load lock (at start-up, and on that type's `.reload dbscripts_on_...` command), and `GetScriptChainMap` answers them under the same lock, NULL for `DBS_INTERNAL` and a type past the last; `CanSpellEffectStartDBScript` says which of a spell's effects starts the spell's script (a script effect before a dummy before a trigger of a spell the client data does not hold, the first of equals), for the dummy and script effects and the loader's check |
| `ScriptNameStore` | the script names and their bindings (`script_binding`), read through `sScriptNameStore`: the names sorted with the empty name first, so that id 0 is no script, and per scripted object type (`SCRIPTED_*`) the script id bound to each entry; `ScriptMgr::LoadScriptNames` fills the names at start-up and `ScriptMgr::LoadScriptBinding` the bindings (at start-up, and on `.reload script_binding` in a debug build, under the store's binding lock); `GetScriptId`, `GetScriptName` and `GetScriptIdsCount` are also free functions for the script library |
| `ChatPacketBuilder` | not a store: the chat message packet for the code below the session, which may not include the session's builder: `World::SetInitialWorldSettings` installs `BuildMessageChatPacket` (`session/packets/chat/`) before anything loads, and `BuildChatPacket` calls it; building with none installed fails an assertion |
| `ResetSchedule` | not a store: when the world's periodic resets next happen, the currency, daily quest, random battleground, weekly quest and monthly quest resets, which `World` keeps in the schedule it installs at construction and moves on as each reset runs; read through `sResetSchedule`, all zeros with none installed |
| `ServerControl` | not a store: the operator's handle on the server for the code below the world: the timed shutdown, the message of the day, whether objects may move, the bans, the configuration and broadcast reloads, the uptime and the world database's version, which `World` implements and installs at construction, and the process's stop request (`ServerControl::StopNow`), which any thread may raise; with none installed the base runs no shutdown, bans nobody and reloads nothing |
| `CommandHooks` | not a store: what the session and the domain ask of the GM command system above them, whether a player may use a command and the run of a command typed in chat; `mangosd` installs the command system's (`ChatHandler::GetCommandHooks`), and the base, with nothing installed, lets no player use a command and drops a line that starts like one |
| `ScriptHooks` | not a store: what the core calls on the script library, its start, free and version and the hooks for gossip, quests, object and item use, area triggers, spell clicks, events, scripted spell effects and auras, and the AI and instance data of a scripted creature, object or map; the core calls them through `sScriptHooks`, which answers the installed hooks or the base, whose every hook answers what a server with no script library answers (false, NULL, and `DIALOG_STATUS_UNDEFINED` for a dialog status); `ServesScript` says whether a script of the library serves a bound name; `mangosd` installs the script dispatcher (`src/scripts/dispatch/`, which hands each hook to SD3's hooks when SD3 is built) before the world starts, `World::SetInitialWorldSettings` starts the library through it where it loads the scripts, and `ScriptHooks::IsInstalled` says whether hooks are installed |
| `DbScriptHooks` | not a store: what the domain asks of the database script engine above it (`ScriptMgr`, `ScriptAction`), the run of a step a map has scheduled (`DbScriptStep`: the step and the objects its script was started for, which the map's schedule holds) and the start of an event (`StartEvents_Event`, which calls the installed hooks); `mangosd` installs the engine's (`ScriptMgr::GetDbScriptHooks`), and the base, with nothing installed, runs no step and ends its script, and takes no event |
| `WorldBroadcast` | not a store: what the code below the world tells every client in it, a system text, a zone under attack, a world defense message, a realm's first achievement and a world state, and the work the map phase leaves for the world thread (`AfterMapPhasePost`), which `World` implements and installs at construction; with none installed the base tells nobody and posts nothing |

Includes are path-qualified (`#include "data/MailLevelRewardStore.h"`): this directory is not on the `game` target's include path. `CheckLayout` classifies every file here as data (`src/tests/tools/layout_gate.py`'s `RULES`), and `CheckHeaderReach` keeps each store's header from reaching `ObjectMgr.h`, the entities, the session, the world, the database and the packets.
