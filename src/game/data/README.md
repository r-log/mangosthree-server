# The data stores (`data/`)

The stores here hold world data loaded once from the world database at start-up (and again on a `.reload`, for a table that has one) and then only read, through lookups. A store is the container and its lookups: it names no entity, session, packet or database type, so the stores build and are tested in `mangos_tests` with no database. The loader that reads the table and validates its rows stays with `ObjectMgr` until the loaders move; `ObjectMgr` owns each store and its getter forwards to the lookup.

| Store | Holds |
|---|---|
| `MailLevelRewardStore` | the mail a character is sent on reaching a level (`mail_level_reward`): per level, the rewards in the order loaded, each for the races in its mask; `ObjectMgr::LoadMailLevelRewards` clears and fills it (at start-up, and on `.reload mail_level_reward` or `.reload all`) and `ObjectMgr::GetMailLevelReward` forwards to its lookup |
| `FishingBaseSkillStore` | the base fishing skill level of an area (`skill_fishing_base_level`): one value per area id, which may be negative, a second value for an area overwriting the first; `ObjectMgr::LoadFishingBaseSkillLevel` clears and fills it (at start-up, and on `.reload skill_fishing_base_level` or `.reload all`) and `ObjectMgr::GetFishingBaseSkillLevel` forwards to its lookup |
| `ExplorationBaseXpStore` | the base XP of exploring an area of a given level (`exploration_basexp`): one value per area level, a second value for a level overwriting the first; `ObjectMgr::LoadExplorationBaseXP` fills it at start-up only (no `.reload` reads the table) and `ObjectMgr::GetBaseXP` forwards to its lookup |
| `PointOfInterestStore` | the points of interest (`points_of_interest`): the map pins a gossip menu can show, one per id, a second point for an id overwriting the first; `ObjectMgr::LoadPointsOfInterest` clears and fills it (at start-up, and on `.reload points_of_interest`, `.reload all_npc`, `.reload all_gossips` or `.reload all`) and `ObjectMgr::GetPointOfInterest` forwards to its lookup; the point names per locale stay with the locales |
| `PageTextStore` | the page texts (`page_text`): the pages of a book, letter or plaque, one per id, each naming the page after it, the store owning each page's text, a second page for an id overwriting the first; `ObjectMgr::LoadPageTexts` reads the rows through `PageTextRepository`, clears and fills it (at start-up, and on `.reload page_text`, `.reload all_item` or `.reload all`), keeps the pages it holds when the table is empty, stops the server when the table cannot be read at start-up, then cuts a circular chain of pages through the store's edit access; `ObjectMgr::ReloadPageTexts` does the same on a reload but keeps the pages it holds when the table cannot be read and answers how the read ended, which `.reload page_text` reports; `ObjectMgr::GetPageText` forwards to its lookup |
| `QuestPOIStore` | the quest points of interest (`quest_poi`, with their points from `quest_poi_points`): per quest, the POIs in the order loaded, each holding its points; `ObjectMgr::LoadQuestPOI` clears and fills it (at start-up, and on `.reload quest_poi`, `.reload all_quest` or `.reload all`), adds each point to its POI through the store's edit access, which leaves an empty entry for a quest only the points table names, and `ObjectMgr::GetQuestPOIVector` forwards to its lookup |
| `CreatureAddonStore` | the creature addons, one store per table (`creature_addon` by spawn guid, `creature_template_addon` by creature entry): the mount, bytes, sheath and PvP states, emote and move flags per key, and the aura list the store owns, 0 terminated or NULL; `ObjectMgr::LoadCreatureAddons` reads both tables through `CreatureAddonRepository` at start-up only (no `.reload` reads them), stops the server when a table cannot be read, checks each addon in ascending key order from 1 (an unknown mount or emote set to 0 through the store's edit access) and turns its aura text into the list, then reports a key whose creature entry or spawn does not exist; the static `ObjectMgr::GetCreatureAddon` and `ObjectMgr::GetCreatureTemplateAddon` forward to the lookups |
| `CreatureEquipmentStore` | the creature equipment templates (`creature_equip_template`): one per equipment id, the main hand, off-hand and ranged items, a second template for an id overwriting the first; `ObjectMgr::LoadEquipmentTemplates` reads the rows through `CreatureEquipmentRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then sets to 0 an item that `Item.dbc` does not hold or that cannot be held in a hand, through the store's edit access, and the static `ObjectMgr::GetEquipmentInfo` forwards to its lookup |
| `CreatureModelInfoStore` | the creature model infos (`creature_model_info`), a `KeyedRecordStore` of `CreatureModelInfo` by display id: the bounding radius, combat reach, gender and the other-gender and alternative display ids; `ObjectMgr::LoadCreatureModelInfo` reads the rows through `CreatureModelInfoRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks each model in ascending order from 1 and each playable race's two models, fixing a bad gender, a redundant or unknown other-gender or alternative id, a bounding radius at or below 0 and a combat reach other than 1.5 through the store's edit access, and the static `ObjectMgr::GetCreatureModelInfo` forwards to its lookup |
| `DungeonFinderStore` | the dungeon finder's data: the requirements to enter a dungeon at a difficulty (`dungeonfinder_requirements`, one entry per map and difficulty), the base XP and money rewards per level (`dungeonfinder_rewards`) and the item rewards per id (`dungeonfinder_item_rewards`), a second entry for a key overwriting the first; `ObjectMgr::LoadDungeonFinderRequirements`, `ObjectMgr::LoadDungeonFinderRewards` and `ObjectMgr::LoadDungeonFinderItems` each clear and fill their own map at start-up only (no `.reload` reads the three tables), and `ObjectMgr::GetDungeonFinderRequirements`, `ObjectMgr::GetDungeonFinderRewards` and `ObjectMgr::GetDungeonFinderItemsMap` forward to it; the dungeon entrances (`lfg_dungeon_entrances`) are held in `LfgDungeonEntranceStore` |
| `InstanceTemplateStore` | the instance templates (`instance_template`): one per instance map, its parent map and its level range, a second template for a map overwriting the first; `ObjectMgr::LoadInstanceTemplate` reads the rows through `InstanceTemplateRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then erases a template whose map is unknown or not instanceable and clears a parent that is unknown or a continent through the store's edit access, and the static `ObjectMgr::GetInstanceTemplate` forwards to its lookup |
| `KeyedRecordStore` | the shared store of records held one to a key (`KeyedRecordStore.h`, a template) for a record type it need not know: lookups by key, a loader's edit access, erase, clear and the highest key; `ObjectMgr` holds the conditions (`conditions`) in one, over `PlayerCondition`, which keeps its checks and its evaluation in `ObjectMgr.h`; `ObjectMgr::LoadConditions` reads the rows through `ConditionRepository` and fills it at start-up, stopping the server when the table cannot be read, `ObjectMgr::ReloadConditions` does the same on `.reload conditions` but keeps the conditions it holds when the table cannot be read and answers how the read ended, which the command reports; both then check the conditions in ascending order, erasing an invalid one, and `ObjectMgr::GetCondition` forwards to its lookup; `ObjectMgr` also holds the creature template spells (`creature_template_spells`) in one, over `CreatureTemplateSpells`, which stays in `Creature.h` for its `CREATURE_MAX_SPELLS` from `Unit.h`: `ObjectMgr::LoadCreatureTemplateSpells` reads the rows through `CreatureTemplateSpellsRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks every row read, in that order, erasing the spells of an unknown creature and setting an unknown spell to 0, and the static `ObjectMgr::GetCreatureTemplateSpells` forwards to its lookup |
| `LfgDungeonEntranceStore` | the LFG dungeon entrances (`lfg_dungeon_entrances`): the entrance position override per dungeon id, read by the dungeon finder's teleport, a second entrance for a dungeon overwriting the first; `ObjectMgr::LoadLfgDungeonEntrances` clears and fills it at start-up only (no `.reload` reads the table), skipping a row whose dungeon is not in `LFGDungeons.dbc`, and `ObjectMgr::GetLfgDungeonEntrance` forwards to its lookup |
| `MultiRecordStore` | the shared store of records held several to a key (`MultiRecordStore.h`, a template): each key's records in the order added, handed out as a pair of iterators that read a record with `->`, a key erased with all its records; `VehicleAccessoryStore` and `SpellScriptTargetStore` are two |
| `SpellScriptTargetStore` | the spell script targets (`spell_script_target`): the creatures and game objects a scripted spell may target, per spell, in the order loaded; `SpellMgr::LoadSpellScriptTarget` reads the rows through `SpellScriptTargetRepository` and fills it at start-up, stopping the server when the table cannot be read; `SpellMgr::ReloadSpellScriptTarget` does the same on `.reload spell_script_target` or `.reload all_spell` but keeps the targets it holds when the table cannot be read and answers how the read ended, which the command reports; both then check every row read, in that order, erasing every target of a spell with a bad row, and `SpellMgr::GetSpellScriptTargets` forwards to its lookup for the spell targeting and checks |
| `VehicleAccessoryStore` | the vehicle accessories (`vehicle_accessory`): the passengers boarded onto a vehicle, per vehicle entry, in the order loaded; `ObjectMgr::LoadVehicleAccessory` reads the rows through `VehicleAccessoryRepository` and fills it at start-up only (no `.reload` reads the table), stops the server when the table cannot be read, then checks every row read, in that order, and erases every passenger of a vehicle whose vehicle or passenger entry is unknown or whose seat is out of range; `ObjectMgr::GetVehicleAccessories` forwards to its lookup, which `VehicleInfo::Initialize` walks to board them |
| `GameConfig` | the server configuration values from `mangosd.conf`, read through `sGameConfig`: `World::LoadConfigSettings` sets them at start-up and on `.reload config`, and `World`'s `getConfig`, `setConfig`, `IsPvPRealm`, `IsFFAPvPRealm`, `GetConfigMaxSkillValue`, `GetDefaultDbcLocale` and `GetAvailableDbcLocale` forward to it; `World` also sets the DBC locale. The visibility distances, the relocation limits and the observer sweep settings are static, set by `World::LoadConfigSettings` and read through `GameConfig::Get...()`. It also holds the visibility distance constants, the `RealmZone` values and the `realmID` declaration |

Includes are path-qualified (`#include "data/MailLevelRewardStore.h"`): this directory is not on the `game` target's include path. `CheckLayout` classifies every file here as data (`src/tests/tools/layout_gate.py`'s `RULES`), and `CheckHeaderReach` keeps each store's header from reaching `ObjectMgr.h`, the entities, the session, the world, the database and the packets.
